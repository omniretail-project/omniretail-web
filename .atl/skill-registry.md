## Project Conventions (from CLAUDE.md + docs/AI_CONTEXT.md)

- `src/core` = shared entities/enums/types/repository contracts (single source, never duplicated: Product, Order, Customer, etc.).
- `src/infrastructure` = simulated backend (MockRepository + MockDatabaseStore + LocalStorage), designed to be swapped for a real API layer later without changing module code.
- `src/modules/<name>` = feature-per-domain: DTOs/mappers/application services stay module-local.
- `src/shared` = UI/hooks/utilities only — **never business logic**.
- `src/config` = navigation, permissions, business presets/policies (`config/navigation.ts` feeds the private shell's `Sidebar`).
- `InventoryMovement` and `AuditLog` are append-only.
- Layered authorization is composed, never substituted: **Authentication != Entitlement (SaaS capability/Plan/Subscription) != Role Permission != Branch Scope != Resource ownership** — a mutation requires ALL of: tenant entitlement AND role permission AND branch access AND resource ownership.
- `BusinessCapabilitiesConfig` (operational config) != SaaS capability (commercial plan entitlement) — `effectiveFeatureEnabled = planHasCapability AND businessConfigSetting`.
- `ResolveTenantEntitlementsService` lives in `shared/application/` (never inside a feature module) so every module can consume it without inverting dependencies. UI reads entitlements exclusively via `EntitlementProvider`/`useEntitlement()` — never `repositories.plans`/`repositories.tenantSubscriptions` directly from a component.
- `feature/*` branches start from `development`, PR back to `development`. Run `npm run lint` + `npm run build` before PR. No force-push on shared branches.
- Never commit/push/merge unless explicitly requested. Conventional commits only, no AI co-author attribution.
- Module ownership (`docs/MODULE_OWNERSHIP.md`): `administration` owns usuarios/roles/permisos, sucursales, business config, **planes/facturación**, proveedores maestro, cuentas bancarias, reportes, auditoría.
